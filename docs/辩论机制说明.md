# 辩论机制说明

## 一、阶段状态机

```
                 ┌──────────────── 硬保险触顶（发言条数 / 耗用额度）
                 ▼
NORMAL(论辩) ──已完成轮数 ≥ roundLimit──► CLOSING(结辩) ──全员结辩完毕──► ENDED(只读)
   ▲                                                                        │
   └──────────────── 续一场（extensionCount < 上限，追加默认轮数）───────────┘
```

阶段与终止判定**只在服务端 `advanceSession()` 一处实现**，前端无法绕过：

- 每次角色发言落库后调用 `advanceSession(sessionId, participantId)`。
- `NORMAL` 阶段：以「本轮已发言人数」判断轮次进度。**一轮完成 = 全员各发过一次**；完成轮数 `≥ roundLimit` 或触顶即切 `CLOSING`，并把所有参与者 `closingDone` 重置为 `false`。
- `CLOSING` 阶段：发言者标记 `closingDone = true`；当全员皆已完成 → 调用 `finalizeSession()` 生成辩要与评点，并把会话置为 `ENDED`（`busy = false`）。
- `ENDED` 后所有写操作（含 SSE `turn`）一律拒绝，仅 `extend`（续场）可改变状态。

## 二、一轮的定义、发言顺序与推进方式

**一轮 = 同席者按座次各发言一次**（辩论赛与议事之通义）。因此：

- 座次由 `DebateParticipant.orderIndex` 决定（即选角顺序）。
- `roundStatus()` 统一计算：已完成的整轮数 `completedRounds = floor(常规发言条数 / 人数)`，进行中的轮次 `activeRound = completedRounds + 1`，并给出本轮`已发言集合`、`待发言者`与`未结辩者`。
- 点「推进本轮」走 `NEXT_ROUND`：服务端在一个 SSE 流内**串行**让本轮所有待发言者依次发言（后一位能读到前一位刚落库的发言），全轮走完才结束响应；若中途轮数已满或触顶而转入结辩，则本轮剩余发言不再进行。
- 结辩阶段同理：一次「完成结辩」让所有未结辩者依次陈词，全部说完即生成辩要（与评点）并封存。
- 用户「@点名」走 `SPECIFY`：只生成被点者的一位发言，不改变整轮推进的判定（判定只看「本轮发言人数集合」）。
- 前端右侧信息栏实时显示「第 n / N 轮」「本轮 x / N 人已发言」「待发言：某某、某某」，按钮文案随状态变化（推进本轮（余 n 人）／推进下一轮／完成结辩（余 n 人））。

## 三、终止条件的四条防线

| 防线 | 默认值 | 说明 |
| --- | --- | --- |
| 轮数上限 | 3（可配 1–10） | 常规轮走完即自动结辩 |
| 发言条数上限 | 60 | 含结辩，触顶即强制收束 |
| 耗用额度上限 | 60000（估算 token） | 触顶即强制收束 |
| 人工收束 | — | 用户随时点「收束成辩要」直接生成辩要并封存 |

**续场**：`ENDED` 后可选「续一场」，条件为 `extensionCount < extendCap`（默认 3）。每次续场追加「默认轮数」的常规轮、清空 `closingDone`、清空上一次判官评点（辩要保留为上一场结果之一，新的辩要在再次结束时覆盖），并回到 `NORMAL`。用尽后彻底封存，不再提供续场入口。

## 四、提示词分层（防人设漂移）

每次生成（单角色单次发言）构造的消息序列：

```
system  = 层1 身份档案（不可变） + 层2 分身差异层（可调） + 层3 论辩通则 + 层4 当前环节规则 + 话题/同席
user…   = 层5 上下文：按该角色视角裁剪的近期交锋
user    = 当前指令（首条为开场指令，其余为「现在轮到你发言。」）
```

- **层1 身份档案**：姓名/字号/朝代/生卒/籍贯/身份、生平、核心思想、性情、言语习惯（自称 + 口癖）、所长、可引之语（附出处）、立言之禁。
- **层2 分身差异层**：性格倾向、语气、知识侧重、立场偏移、额外设定、约束强度（1–5，附释义）。明确声明「与档案冲突时以档案为准」。
- **层3 论辩通则**（全文展示于后台）：① 时代一致——不得提及卒年之后的人事与器物，不得用现代词汇/外语词/网络语，不得自认 AI，不得预知后世评价；② 语体一致——用其自称与习惯用语；③ 立场一致——不为迎合而改易，被说服须有据让步；④ 交锋要求——必先回应最近发言者的具体观点，再申己论，不得自说自话；⑤ 输出格式——纯正文，限字数，不加标题/「某某曰」前缀/括号动作/Markdown。
- **层4 环节规则**：常规轮（首轮立论、其后驳论，限 `speechMaxChars`）；结辩（回顾己方要点 → 回应最有力反驳 → 一句定论，限 `closingMaxChars`）。
- **语体层**（新增）：会话创建时可选 `随人物 / 文言 / 半文半白（默认）/ 白话`，存于 `DebateSession.language`，并在每次发言的 system 中注入对应写法要求（`plain` 时明确要求现代白话、但仍禁网络语与 AI 措辞；`auto` 时按朝代取舍——先秦秦汉多文言，近世转浅近）。语体只定文白与句式，人物的自称、称谓与口癖一律仍照档案。辩要与判官评点沿用同一语体。
- **层5 上下文裁剪**：只保留最近 12 条发言；**自身发言放入 `assistant` 轮**，他人发言以 `【某某】内容` 进入 `user` 轮，用户/主持消息以 `【问者】/【主持】` 前缀进入 `user` 轮；若更早内容被截断，会插入一条说明（要求依己方立场作答而非编造引文）。

辩要与评点使用**独立模板**：辩要走「记室」视角，只归纳交锋焦点与各家主张，不判胜负；评点走「判官」中立视角，从史实贴合度、论证质量、立场偏移三点评析。两者均不作现代术语、不虚构发言。

## 五、生成与持久化

- 每次「推进」对应一次请求：`NEXT_ROUND` 在该请求内**串行**生成整轮（每人一次，后一位必须读到前一位发言才能有效反驳，故不并行）；`SPECIFY` 只生成一位。
- 流式：服务端 `ReadableStream` 转发上游 SSE 增量，前端打字机渲染。
- **落库时机**：流结束后一次性写入 `Message`（含估算 token）；用户中断时保存已生成片段并标 `truncated`，不逐 token 写库。
- 并发控制：会话级 `busy` 位 —— 生成期间再次请求返回 409；前端同时禁用按钮。
- 中断：请求级 `AbortController`，前端关闭 reader 与后端流联动，避免僵尸请求；上游超时由 `llm.timeoutMs` 控制。

## 六、接口契约

### `POST /api/debate/[id]/turn`

请求体：

```jsonc
{ "action": { "type": "NEXT_ROUND" } }
{ "action": { "type": "SPECIFY", "participantId": "..." } }
{ "action": { "type": "USER_INTERJECT", "content": "...", "asModerator": true } }
```

- `USER_INTERJECT` 不调模型，**返回 JSON**：`{ ok, messageId, streaming: false }`。
- 其余动作返回 `text/event-stream`，事件序列：

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `meta` | `participantId, speakerName, kind, sealChar, inkColor, dynasty, round, phase, index, total` | 某位开始发言，前端据此建立气泡（印章字与配色直接取自参与者，避免错显） |
| `delta` | `text` | 文本增量 |
| `segment` | `participantId, speakerName, round, phase, truncated, ended, nextPhase` | **一位说完并已落库**，前端把流式内容固化为一条消息 |
| `error` | `message` | 生成失败（未配置密钥、上游报错、超时等） |
| `done` | `phase, ended, spokeCount, session{...}` | 整轮（或单次点名）结束；`session` 携带最新阶段、轮次、`summary`、`judgment` |

### 其余接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/debate/[id]/summary` | 提前收束：生成辩要（与评点）并封存 |
| POST | `/api/debate/[id]/extend` | 续一场：追加轮数回到进行中 |
| GET | `/api/debate/[id]/export` | 导出 Markdown（`Content-Disposition: attachment`） |
| POST | `/api/admin/test-connection` | 模型连通性测试（可传临时 base_url/api_key/model），不记录密钥 |

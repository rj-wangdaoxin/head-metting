# 需求规格说明

## 一、产品定位

「青史群贤」是一个以中国古代历史人物为本体的智能体平台。人物不是泛化的角色设定，而是**由史料固化、不可修改的档案**驱动：生平、思想、性情、语体、可引之语、立言之禁共同构成其身份，模型只能在此约束内立言。

三条核心链路：**人物库 → 分身 → 论辩**。

## 二、核心需求

### 1. 人物库（不可变基础数据）

| 项 | 要求 |
| --- | --- |
| 分类筛选 | 文官 / 武将 / 谋士 / 诗人 / 作家 / 思想家 / 帝王 / 其他 |
| 朝代筛选 | 不限 → 先秦、秦汉、三国两晋南北朝、隋唐、宋、元、明、清（最晚至清） |
| 检索 | 姓名、字号、思想、专长、生平关键词 |
| 档案内容 | 生卒年、籍贯、身份官职、生平、核心思想、性格关键词、语言风格（自称/口癖/句式）、代表言论（附出处）、典故轶事、所长、立言之禁、史料来源、头像 |
| 不可变性 | 档案仅由 `prisma/seed.ts` 从 `seed/figures/*.json` 写入；应用层无任何编辑入口，后台只能启停与替换头像 |
| 数量 | 首版 40 人，覆盖 8 个朝代与全部类型，可增量扩充 |

### 2. 分身系统

- 每个本体对应一个「官方本体」，用户可据本体创建**个人分身**。
- 分身只存「差异层」：分身名、性格倾向、语气风格、知识侧重、立场偏移、额外设定、人设约束强度（1–5）。
- 分身继承本体的全部不可变史实与头像；差异层与档案冲突时**以档案为准**。
- 支持创建、调整、复制、删除；已入场的分身若被删除，历史辩录仍完整可读（会话保存了参与者快照）。

### 3. 话题辩论（含硬性终点）

- 发起话题（可附背景）→ 选角（官方本体与我的分身可混选，上限后台可配，默认 3）→ 设定轮数（默认 3，可配 1–10）→ 可选是否生成判官评点。
- 交互：轮次制自动推进（按座次依次发言）＋ 可「@点名」指定某人发言 ＋ 用户可插话或切换为主持身份下达指令 ＋ 可随时中断。
- **结束规则**：
  1. 常规轮走完（每轮每角色各发言一次）后自动进入**结辩**，各作短陈，全部结辩完成即封存；
  2. **硬保险**：单场发言条数上限（默认 60）或累计耗用额度上限（默认 60k）任一触顶，立即强制收束结辩；
  3. 用户可随时「收束成辩要」提前结束；
  4. 结束后会话**只读**，可回看 / 导出；需继续须显式「续一场」，受续场次数上限（默认 3）与总轮数硬顶约束，用尽即彻底封存。
- 结束后产出：**辩要**（交锋焦点与各家主张）+ **判官评点**（中立视角的论证质量与史实贴合度评析，可开关）。
- 每位角色的发言须严格符合其历史背景与鲜明特色，不得越时代、不得提及自身卒年之后的人事、不得自认 AI。

### 4. 后台配置

- 模型：`base_url`、`api_key`（脱敏输入）、`model`、`temperature`、`max_tokens`、超时、连接测试。
- 论辩：参与人数上限、轮数下限/上限/默认值、常规发言字数、结辩字数、发言条数上限、耗用额度上限、续场次数上限、判官评点默认开关。
- 人物：启停开关（只影响选角面板可见性）、头像来源管理与替换。
- 提示词模板只读查看。

## 三、非目标（首版不做）

- 登录与多用户隔离（本地单用户）；用户间分享与协作。
- 运行时联网抓取人物资料（资料在构建期固化）。
- 语音、图片生成式头像、多人实时同屏（辩论为轮次制，逐条生成）。
- 编辑内置人物历史字段（设计上明确禁止）。

## 四、约束与假设

- 运行环境：Node 18+（实测 Node 24）、Windows/macOS/Linux 均可；SQLite 单文件库。
- 模型需兼容 OpenAI `/chat/completions` 且支持 `stream: true`。
- 人物数据须可溯源：代表言论必须附出处，生卒不确定者记 `null` 并在生平中说明，不得编造。

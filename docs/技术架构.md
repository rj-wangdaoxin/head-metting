# 技术架构

## 一、选型

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 15（App Router）+ TypeScript | 页面与 API 同仓，单命令启动 |
| 样式 | Tailwind CSS 3.4 + 自定义水墨令牌 | 令牌见 `tailwind.config.ts`（ink / paper / cinnabar / indigo / moss / gold） |
| 数据 | Prisma + SQLite（`prisma/dev.db`） | 单文件库，便于本地使用；`prisma db push` 免交互 |
| 模型 | 自研 OpenAI 兼容客户端（原生 `fetch` + 手写 SSE 解析） | 不引入 SDK，避免各家兼容层差异，便于 `AbortController` 中断 |
| 校验 | zod | 种子数据（脚本）与 Server Action 入参 |
| 图片 | sharp（构建期脚本 / 后台上传） | 统一压缩为 256×256 JPEG |
| 图标 | lucide-react | 少量线性图标 |

## 二、渲染与数据流

```
页面（RSC，直读 Prisma）───► 展示型数据：人物库 / 档案 / 分身 / 辩录 / 后台
        │
        ├─► Server Actions（`src/lib/actions/*`）──► 写操作：分身 CRUD、后台配置、启停、头像
        │
        └─► Route Handler（`/api/debate/[id]/*`）──► SSE 流式生成（Server Action 不适合长流）
                     │
                     ├─► `lib/debate.ts`  轮次编排 / 阶段状态机 / 落库 / 导出
                     ├─► `lib/prompt.ts`  四层提示词 + 常规/结辩/判官三套模板
                     └─► `lib/llm.ts`     OpenAI 兼容流式客户端（超时、中断、错误归一）
```

## 三、数据模型（`prisma/schema.prisma`）

| 模型 | 关键字段 | 说明 |
| --- | --- | --- |
| `Figure` | `slug`(uniq)、`dynasty`+`dynastyOrder`、`category`、生卒/籍贯、`roles/personalityTraits/speakingStyle/thoughts/quotes/anecdotes/expertise/taboos/sources`（JSON 字符串）、`inkColor`、`avatarUrl/avatarKind/avatarSource`、`enabled` | 不可变基础数据，只由 seed 写入 |
| `Persona` | `figureId`、`name`、`personalityOverride`、`toneStyle`、`knowledgeFocus`、`stanceShift`、`extraPrompt`、`strictness` | 只存差异层，级联删除于 Figure |
| `DebateSession` | `topic`、`background`、`maxParticipants`、`roundLimit`、`currentRound`、`phase`、`status`、`busy`、`messageCount`、`tokenUsed`、`extensionCount`、`allowJudgment`、`summary`、`judgment` | 一场论辩；阶段与终止的唯一事实来源 |
| `DebateParticipant` | `sessionId`、`kind`(FIGURE/PERSONA)、`figureId`、`personaId`、`displayName`、`dynastyLabel`、`categoryLabel`、`inkColor`、`sealChar`、`avatarUrl`、`orderIndex`、`closingDone` | **快照**设计：即使本体/分身后续变化，历史辩录仍自洽 |
| `Message` | `sessionId`、`participantId?`、`roleType`(FIGURE/PERSONA/USER/MODERATOR/SYSTEM)、`speakerName`、`round`、`phase`、`content`、`truncated`、`tokens` | 发言记录 |
| `Setting` | `key`、`value` | KV 配置：`llm.*`、`debate.*`；读取时与 `DEFAULT_SETTINGS` 合并 |

JSON 字段以字符串存放（SQLite 无原生 JSON 类型），读写经 `parseJson` / `toJson` 转换。

## 五、可靠性与观测

- **错误归一**：`LlmError` 携带 `status` 与截断的错误体；日志只记录状态码与摘要，**不打印密钥与完整请求体**，正常生成不打印正文。
- **超时与中断**：`llm.timeoutMs`（默认 120s）与请求级 `AbortSignal` 双向联动。
- **并发**：会话 `busy` 位 + 前端按钮禁用双保险；`busy` 在流结束的 `finally` 中释放。
- **失败降级**：辩要/评点生成失败会把错误摘要写入对应字段而非中断收尾流程；头像抓取失败回退默认头像。
- **成本控制**：上下文只保留最近 12 条发言；`max_tokens` 可配；单场设 `tokenBudget` 硬顶。

## 六、安全与隐私

- 免登录、纯本地运行；`prisma/dev.db` 与 `.env` 均在 `.gitignore` 中。
- `api_key` 仅存本地 SQLite，界面以密码框呈现；连接测试可用临时值而不落库。
- 人物档案不可编辑（应用层白名单只允许 `enabled` 与头像三字段）。

## 七、扩展建议

- **新增人物**：向 `seed/figures/<朝代>.json` 追加一条 → `npm run validate:figures` → `npm run db:setup`。
- **新增类型/朝代**：改 `src/lib/constants.ts` 的枚举与颜色映射（`DYNASTY_ORDER`、`DYNASTY_COLOR`、`CATEGORY_SYMBOL`），同步更新校验脚本枚举。
- **换模型供应商**：后台改 `base_url` 与 `model` 即可；若供应商响应体不是 `choices[0].delta.content`，只需调整 `lib/llm.ts` 的解析处。
- **多用户/云端部署**：将 SQLite 换成 PostgreSQL（改 `datasource`），为 `Persona`/`DebateSession` 增加 `ownerId`，并在 Server Action 与查询层加过滤。
